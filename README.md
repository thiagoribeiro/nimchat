# NimChat

NimChat is a web and Android chat client for [Nimlet](https://github.com/thiagoribeiro/nimlet)
with first-class support for [BRIAN](https://github.com/thiagoribeiro/brian) rich blocks.
Approvals, checklists, polls, forms, workflows and agent activity render as interactive
cards and "surfaces" next to the conversation. Interactions go back to the server as
auditable `m.plugin.command` events, which [agent-blocks](https://github.com/thiagoribeiro/agent-blocks)
processes.

```text
packages/sdk/     TypeScript SDK: auth, rooms/events, /sync loop, zustand stores, command queue
packages/brian/   BRIAN projection: validators, surfaces, plugin views, monthly bills logic
packages/i18n/    gettext-style translations (English source, pt-BR catalog)
apps/web/         Next.js 13 web app
apps/mobile/      Expo / React Native app (Android)
```

The UI follows the browser or device language. English is the default, and Brazilian
Portuguese is included.

## Requirements

- Node.js 20+ and npm (npm workspaces).
- A running Nimlet server. The web app calls it directly from the browser, so Nimlet must
  allow your web origin.
- For interactive BRIAN cards: an agent-blocks deployment, and the user IDs of its publisher
  and of your agents. Without them, cards render as read-only fallbacks.

## Development

```sh
npm ci
npm test            # unit tests in every workspace
npm run typecheck
```

### Web

```sh
cp apps/web/.env.example apps/web/.env.local   # set NEXT_PUBLIC_NIMLET_URL
npm run dev --workspace @nimchat/web
```

Release build (`npm run build:release --workspace @nimchat/web`) refuses to run without
`NEXT_PUBLIC_NIMLET_URL`, `NEXT_PUBLIC_BRIAN_AGENT_IDS` and `NEXT_PUBLIC_BRIAN_PUBLISHER_IDS`.
These values are inlined at build time. The `Dockerfile` at the repository root builds the
standalone web server and takes them as build args.

End-to-end tests run against a mocked backend at `https://nimlet.test` in pt-BR:

```sh
NEXT_PUBLIC_NIMLET_URL=https://nimlet.test NEXT_PUBLIC_BRIAN_AGENT_IDS=review-agent \
  NEXT_PUBLIC_BRIAN_PUBLISHER_IDS=review-publisher NEXT_PUBLIC_BRIAN_SHARING_ENABLED=true \
  NEXT_PUBLIC_BRIAN_MONTHLY_BILLS_ENABLED=true npm run build --workspace @nimchat/web
npx playwright install chromium   # or set PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH
npm run test:e2e --workspace @nimchat/web
```

### Android

```sh
cp apps/mobile/.env.example apps/mobile/.env   # set EXPO_PUBLIC_NIMLET_URL and BRIAN IDs
cd apps/mobile
npx expo prebuild -p android
npm run build:release        # ./gradlew assembleRelease with the release JS bundle
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

- `android/` is generated by `expo prebuild` and not tracked.
- Use JDK 21: newer JDKs break React Native 0.86's CMake steps.
- Build `assembleRelease`, not `assembleDebug`. Debug builds don't embed the JS bundle and
  wait for Metro forever.
- The template signs release builds with the debug keystore. Configure your own signing
  config before distributing an APK.
- Set your own `android.package` in `apps/mobile/app.json` if you publish a fork.

**Push notifications.**
- Add an Android app in Firebase with your package name and save its config as
  `apps/mobile/google-services.json` (not tracked). `expo prebuild` wires it in.
- The server side needs a Firebase service-account key; see `NIMLET_FCM_CREDENTIALS_FILE`
  in Nimlet.
- Pushes carry only metadata (room and counts), never message content.

## Configuration

| Web | Mobile | Purpose |
|---|---|---|
| `NEXT_PUBLIC_NIMLET_URL` | `EXPO_PUBLIC_NIMLET_URL` | Nimlet server URL (required). |
| `NEXT_PUBLIC_NIMLET_NAMESPACE` | `EXPO_PUBLIC_NIMLET_NAMESPACE` | Nimlet namespace (default `default`). |
| `NEXT_PUBLIC_BRIAN_AGENT_IDS` | `EXPO_PUBLIC_BRIAN_AGENT_IDS` | Comma-separated agent user IDs trusted to delegate. |
| `NEXT_PUBLIC_BRIAN_PUBLISHER_IDS` | `EXPO_PUBLIC_BRIAN_PUBLISHER_IDS` | Comma-separated publisher user IDs trusted for plugin state. |
| `NEXT_PUBLIC_BRIAN_SHARING_ENABLED` | `EXPO_PUBLIC_BRIAN_SHARING_ENABLED` | Shared surfaces (needs agent-blocks room-admin). |
| `NEXT_PUBLIC_BRIAN_MONTHLY_BILLS_ENABLED` | `EXPO_PUBLIC_BRIAN_MONTHLY_BILLS_ENABLED` | Monthly bills plugin UI. |
| `NEXT_PUBLIC_BRIAN_SURFACE_NAMES_ENABLED` | `EXPO_PUBLIC_BRIAN_SURFACE_NAMES_ENABLED` | Renaming surfaces. |

## Translations

Strings are written in English and wrapped in `t()` from `@nimchat/i18n`:

```ts
t("Invite to {name}", { name });
tn(count, "{count} new message", "{count} new messages");
```

Translations live in `packages/i18n/src/pt-BR.ts`. Messages that the server sends in
English, such as form errors, are passed through `t()` when displayed. Never call `t()` at
module load: keep English keys in tables (mark them with `msg()`) and translate when
rendering.

## Known issues

- **Two React majors in one workspace.** `apps/web` uses React 18 (Next 13.4) and
  `apps/mobile` uses React 19 (Expo SDK 57). npm nests the right runtime copies, but some of
  the mobile app's transitive `@types/react` resolve to the root copy. That can surface as
  type errors in `apps/mobile`, never at runtime.
- **`swcMinify: false` in `apps/web/next.config.js` is required.** SWC's minifier breaks
  `emoji-mart` in production builds only.
